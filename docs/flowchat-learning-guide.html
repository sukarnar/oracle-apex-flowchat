A learning guide for FlowChat

A friendly helper that fills in forms by chatting

Forms are big sheets full of empty boxes. FlowChat is a helper who asks you one question at a time, listens, and writes each answer into the right box for you.

This guide explains it the way you would explain it to a five-year-old. Each idea also shows its grown-up word so you can find it in the real tool.

    Chapter 4

    Every stone, up close

    Now let's open each stone and look inside. For every stone you'll see when to use it, the settings it has, a tiny chat to show what the person sees, and the real recipe the drawing board saves for you.

    Adding any stone takes the same five steps

    1. In the drawing board, click the stone in the list on the left. It appears on the map.
    2. With the stone selected, fill in its settings in the Properties tab on the right.
    3. Draw its arrows: drag from a little dot at the bottom of the stone to the next stone, or pick the next stone under Connections.
    4. Open the Test tab and chat with your map. Nothing real is sent or saved there; pretend answers stand in for databases, emails and websites.
    5. Press Save draft while you work, and Publish when it's ready. Each publish gets a new version number. (Without the database, use Export JSON to save the map as a file.)

    You never have to type the recipes below by hand. The drawing board writes them. They're here so you can see what each setting means.

    Chapter 5

    The team that makes it work

    FlowChat is not one thing. It is a small team, and each member has one job.

    ✎

    The drawing board

    Where a grown-up draws the map with boxes and arrows, then tests it with pretend answers.

    designer
    ⌘

    The map

    The finished drawing, saved as a list of stones and arrows. It can have version numbers, like "map 1" and "map 2".

    flow JSON
    ⚙

    The brain

    Reads the map, checks every answer, and decides what to say next. There are twin brains that follow the same rules: one lives in the database, one in the web page.

    engine: PL/SQL and JS
    ☺

    The chat window

    The little window with bubbles and buttons that you see and type into.

    widget
    ▦

    Snap-on bricks

    Ready-made pieces that snap the drawing board and the chat window into an Oracle APEX app, like building blocks.

    region plugins

    The chat window never decides anything by itself. It only shows what the brain says and sends back what you typed. That way nobody can cheat by poking at the web page.

    Chapter 6

    How the helper keeps you safe

    It checks every answer

    If the map says "1 to 3 scoops" and you type 7, the helper kindly says no and asks again. The brain checks, not the chat window, so nobody can sneak past. validation

    Secrets stay secret

    Private things, like a phone number, are hidden in the notebook where the helper writes down what happened. The robot helper only ever sees a sticker like [PII_1] instead of the real secret. PII masking and placeholders

    Only call numbers on the fridge

    The helper can phone other computers to ask things, but only the ones a grown-up wrote on the approved list. The map can't add new numbers, and the passwords stay locked in a drawer. FC_REST_ENDPOINTS and Web Credentials

    "Are you sure?" before big things

    Before saving or changing anything important, the helper reads it back and waits for you to say yes. If someone else changed the same thing first, it tells you instead of overwriting it. confirm and conflict check

    Chapter 7

    The clever robot stone

    Most stones do exactly what the map says. One special stone holds a clever robot that can think. You give it a goal, like "help Sam ask for time off", and it works out which questions to ask. Agent node with an AI model

    The robot has a toolbox. It can only use the tools a grown-up put in it: look something up, find a record and let you pick it, phone an approved computer, or fill in a box. tools, skills, pick_record, set_field

    The robot never talks to you behind the brain's back. Every question it asks goes through the brain, which checks your answer the normal way. If the robot gets stuck or tries too many times, the brain stops it and takes another path. limits and onError
